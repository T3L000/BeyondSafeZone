# 《保护区之外》详细策划案

更新日期：2026-06-05

## 1. 详细策划目标

本文件把系统策划案中的规则落到开发可执行层面。重点说明程序、界面、场景、剧情、美术、音效各部分需要做什么。

近期制作范围以 `docs/MINIMUM_DEMO_SCOPE.md` 为准：先完成 10-15 分钟最小可玩纵切，证明“隐藏 AI 主角改写玩家生存路线”成立。本文中涉及 14 地点、40+ 房间、完整红潮夜、完整二周目和回放动画的内容，均作为后续扩展或参考资料，不作为近期最小 Demo 的验收要求。

### 1.1 当前开发平台口径

- 主开发目标：Unity 2D 灰盒 Demo。
- 当前 Unity 主工程路径：`E:\Download\working\BeyondSafeZone\BeyondSafeZoneUnity`。
- 旧的兄弟 Unity 工程目录 `E:\Download\working\BeyondSafeZoneUnity` 已废弃，不再作为开发目标。
- 当前实现以 `BeyondSafeZoneUnity/Assets/Scripts/**`、`BeyondSafeZoneUnity/Assets/Tests/**` 和 `BeyondSafeZoneUnity/Assets/Scenes/**` 为准。
- PlayKit.ai 使用 Unity SDK 接入，只负责异常档案、祁眠日志、NPC/广播/独白等文本增强；本地规则负责所有玩法结算。

### 2.3 关键状态字段

| 字段 | 含义 |
|------|------|
| `state.day` | 当前天数 |
| `state.phase` | 当前阶段 |
| `state.resources` | 基础资源 |
| `state.lin` | 林行状态 |
| `state.shelter` | 据点状态 |
| `state.bike` | 自行车状态 |
| `state.car` | 汽车修理状态 |
| `state.car_parts` | 电瓶、汽油、轮胎 |
| `state.locations` | 共享地点状态 |
| `state.qimian` | 祁眠状态、人格卡、日志 |
| `state.anomaly_dossier` | 一周目未知行动者档案 |
| `state.evacuation` | 撤离旗标 |
| `state.reveal` | 通关揭示 |

地点状态新增字段：

| 字段 | 含义 |
|------|------|
| `location.anomaly_tags` | 林行可发现的异常标签，如 `picked_lock`、`missing_portable_food`、`moto_tire_trace` |
| `location.player_mark` | 林行留下的当前标记：`danger`、`help`、`route`、`reserved_supply` 或 null |
| `location.player_mark_day` | 标记留下的天数，用于过期和日志展示 |
| `location.player_reserved_resources` | 玩家主动保留给未知行动者/幸存者的物资类型与数量 |

未知行动者档案结构：

```text
state.anomaly_dossier = {
  entries: [
    {
      day: int,
      location_id: string,
      anomaly_tag: string,
      evidence_text: string,
      inference_tags: ["cautious", "has_motorcycle"],
      verified: bool
    }
  ],
  known_patterns: ["会避开破坏", "可能会帮助近处的人"],
  player_hypotheses: ["不是普通幸存者", "有夜间载具"]
}
```

## 3. 机制流程

### 3.1 每日流程

| 顺序 | 阶段 | 处理 |
|------|------|------|
| 1 | 清晨 | 应用每日事件、状态文本、广播线索 |
| 2 | 白天 | 玩家选地点并进入搜索 |
| 3 | 搜索 | 房间搜索，获得资源/线索/伤病 |
| 4 | 黄昏 | 离开地点，更新异常档案，可留下标记 |
| 5 | 夜晚 | 玩家执行一个据点行动 |
| 6 | 祁眠 | AI 读取可感知标记并执行夜间任务 |
| 7 | 结算 | 消耗资源、处理夜晚压力、进入下一天 |

### 3.2 探索流程

```text
选择地点
→ 检查自行车范围
→ 应用路况疲劳
→ 建立搜索阶段
→ 选择房间
→ 可选引诱
→ 谨慎/快速搜索
→ 结算资源、旗标、伤病、感染、噪音
→ 检查异常痕迹并写入档案
→ 可选择留下标记或保留物资
→ 时间达到上限或主动离开
```

### 3.3 祁眠 AI 流程

```text
day < 5：无行动
day >= 5：awake = true
检查固定日程
  有固定任务：执行固定任务
  无固定任务：进入动态 AI
动态 AI：
  perceive
  collect_tasks
  rank_and_select
  execute
  update_ai_state
  append_log
```

### 3.4 异常发现流程

```text
林行进入地点或次日打开节点地图
→ 系统检查 location.anomaly_tags
→ 将未读异常转成玩家可见文本
→ 写入 state.anomaly_dossier.entries
→ 根据标签更新 known_patterns / player_hypotheses
→ 地点卡显示“未知行动者档案 +1”或问号图标
```

Demo 期优先实现 6 类异常：

| 标签 | 来源字段 | 可见文本目的 |
|------|----------|--------------|
| `picked_lock` | `lock_state = "picked"` | 证明有人安静进入 |
| `missing_portable_food` | 便携食物减少 | 证明对方有选择地取物 |
| `moto_tire_trace` | 祁眠任务写入 | 证明对方有摩托 |
| `zombie_diverted` | `zombie_count` 或 `danger_level` 下降 | 证明尸群被处理 |
| `anonymous_medicine` | 药品新增或留包 | 证明对方不完全敌对 |
| `fluorescent_mark` | `qimian_mark` 非空 | 证明对方有标记语言 |

### 3.5 留标记流程

```text
林行准备离开地点
→ 如果 day >= 5 且地点允许留标记
→ 显示标记选择弹窗
→ 玩家选择 danger/help/route/reserved_supply 或跳过
→ 写入 location.player_mark、player_mark_day、reserved_resources
→ 黄昏结算保存到共享地图
```

限制：

- 每天最多留下 1 个主动标记，避免 UI 和数值复杂度失控。
- 标记默认 2 天后过期。
- 标记不是“命令祁眠”，只改变祁眠 AI 的任务权重。
- 玩家不能知道祁眠是否一定会响应，只能在次日或后续地点变化中验证。

### 3.6 祁眠读取标记流程

```text
祁眠 AI perceive
→ 收集 day 内未过期 player_mark
→ 将标记加入 perceivable_state.player_marks
→ help 标记提高 rescue/supply_drop/leave_medicine 权重
→ danger 标记提高 clear_route 或避开该区权重
→ route 标记提高 patrol/clear_bridge/zombie_diversion 权重
→ reserved_supply 让祁眠优先判断“是否取用任务所需”而不是清空资源
→ 日志记录 world_trace_input，通关后展示
```

## 4. UI 部分

### 4.1 主界面需求

主界面必须显示：

- 当前天数和阶段。
- 林行状态。
- 基础资源。
- 汽车零件和修理进度。
- 当前事件文本。
- 可操作按钮。

### 4.2 节点地图需求

节点地图卡片必须显示：

- 地点名称。
- 圈层。
- 路程和路况。
- 危险等级。
- 资源倾向。
- 是否可达。
- 是否有祁眠异常痕迹。
- 是否有未读异常档案。
- 是否存在玩家留下的标记。

### 4.3 房间搜索界面需求

房间卡片必须显示：

- 房间名。
- 能见度。
- 搜索耗时。
- 是否上锁。
- 是否已搜索。
- 隐藏丧尸风险提示。

操作按钮：

- 谨慎搜索。
- 快速搜索。
- 制造声音引开。
- 留下标记。
- 离开地点。

### 4.4 未知行动者档案界面需求

展示内容：

1. 异常时间线。
2. 地点和证据文本。
3. 推断标签。
4. 玩家留下过的标记。
5. 后续是否得到反馈。

档案文本要保持林行视角，不出现“祁眠 AI”“人格卡”等后台词。

### 4.5 标记选择弹窗需求

进入时机：离开地点前。

按钮：

- 危险标记。
- 求助标记。
- 路线提示。
- 保留物资。
- 不留下。

每个按钮要写清楚“这只是留下痕迹，不保证有人回应”。

### 4.6 通关日志界面需求

展示顺序：

1. 祁眠人格卡。
2. 每日 AI 行动列表。
3. 每条日志展开：输入、候选、规则、结果、地图影响、主观残句。
4. 展示对应的玩家可见异常和玩家标记如何进入祁眠感知。
5. Day 15 双层揭示。

### 6.1 必须写清的剧情节点

|------|----------|

### 6.2 祁眠日志格式

每条日志包含：

- 日期。
- 标题。
- 玩家一周目可见线索。
- 真相说明。
- AI 回放。
- 玩家可见异常/标记输入。
- 主观残句。

## 10. 范围控制

### 近期最小 Demo 必须做

- 15 天叙事框架下的 10-15 分钟最小可玩纵切。
- 4 个核心地点：据点、诊所、超市、修理铺/车库。
- 祁眠 AI 隐藏行动。
- 共享地图改写。
- 简化汽车撤离目标。
- 异常调查档案。
- 隔空标记。
- 通关日志揭示。
- 1 条完整诊所 AI 因果链：药柜异常、求助标记、祁眠读取、匿名反馈、日志解释。

### 近期不做完整承诺

- 完整开放世界。
- 完整第二周目 15 天循环。
- 复杂动作战斗。
- 保护区经营。
- 祁烬可操作线。
- 大量 NPC 支线。
- 14 地点全量实现。
- 40+ 房间全量实现。
- 复杂行动点/骰子系统。
- 5 段回放动画。
