# BeyondSafeZone 架构重构设计报告

> 目标：将当前 1464 行单体文件拆分为分层架构，实现规则-表现-配置分离，为侧视横版迁移和二周目打好地基。
> 原则：不新增功能，不改变游戏行为，仅重组现有代码。

---

## 一、当前架构诊断

### 1.1 文件现状

```
game/
├── scripts/
│   ├── core/
│   │   └── game_simulation.gd    ← 1464 行，承载全部职责
│   └── main.gd                   ← 380 行，直读 sim.state 字典
├── tests/
│   └── test_game_simulation.gd
└── scenes/
    └── main.tscn

总计：2 个功能脚本 + 1 个测试。game_simulation.gd 承担了 7 个独立职责。
```

### 2.2 每个脚本一句话职责

| 脚本 | 职责 |
|------|------|
| `game_state.gd` | 定义游戏状态字典结构，提供 `new_game()` 工厂 |
| `game_simulation.gd` | 管理天/阶段流转（morning→day→searching→evening→night→reveal） |
| `exploration.gd` | 判断地点可达性、计算搜索结果、返回资源和风险 |
| `shelter.gd` | 设施使用/建造/修理逻辑，返回事件文本 |
| `night_resolver.gd` | 血月/红潮/噪音传播/感染结算，返回夜晚事件列表 |
| `qimian_ai.gd` | 感知→收集任务→排序→执行，返回日志条目 |
| `car_system.gd` | 汽车发现/4 步修理/零件消耗/就绪判断 |
| `game_manager.gd` | 信号路由中心：`UI 发信号 → Manager 调规则层 → Manager 通知 UI 刷新` |
| `main_ui.gd` | 组装所有面板，监听 Manager 的刷新信号 |
| `events_15d.gd` | `const DAY_EVENTS = {1: {...}, 2: {...}, ...}` |
| `locations.gd` | `const LOCATIONS = {...}` + `const ROOMS_FOR = {...}` |
| `constants.gd` | `const MAX_DEMO_DAY = 15` 等全局常量 |

### 2.3 数据流（所有功能统一模式）

```
┌─────────────┐    信号     ┌──────────────┐   调用    ┌─────────────┐
│   UI 层     │ ──────────→ │  GameManager  │ ────────→ │  规则层     │
│ (main_ui)   │ ←─ 刷新 ─── │  (路由中心)   │ ← 结果 ── │ (sim/系统)  │
└─────────────┘             └──────────────┘           └─────────────┘
                                                                  │
                                                           读取配置
                                                                  │
                                                          ┌─────────────┐
                                                          │  数据配置层  │
                                                          │ (纯字典)     │
                                                          └─────────────┘
```

**铁律**：
- UI 发信号，不读规则层内部
- 规则层算结果返给 Manager，不碰 UI
- Manager 是唯一知道"谁调用谁"的枢纽
- 配置层是纯字典/数组，不含函数

## 三、各层详细设计

### 3.1 数据配置层（data/）

**原则**：每个文件只导出一个 `const` 字典，零函数。

```gdscript
# data/constants.gd
class_name GameConstants
const MAX_DEMO_DAY := 15
const BLOOD_MOON_DAYS := [7, 15]
const RED_TIDE_DAYS := [11, 12, 13, 14]
```

```gdscript
# data/events_15d.gd
class_name DayEvents
static func get(day: int) -> Dictionary:
    return _DAY_EVENTS.get(day, _fallback(day))
const _DAY_EVENTS := {
    1: {morning_text="...", pressure_type="tutorial", clue="...", ...},
    2: {...},
    # ... 全部 15 天
}
```

```gdscript
# data/locations.gd
class_name LocationData
static func get_all() -> Dictionary:
    return _LOCATIONS
static func rooms_for(location_id: String) -> Dictionary:
    return _ROOMS.get(location_id, _default_rooms())
const _LOCATIONS := {
    "home": {name="林行家", ring="近圈", range=1, ...},
    # ... 全部 14 地点
}
const _ROOMS := {
    "home": {"living_room": {name="客厅", ...}, ...},
    # ... 全部 40+ 房间
}
```

**关键收益**：后续调平衡只需改数据文件中的数字，不碰逻辑代码。

### 3.2 状态层（game_state.gd）

```gdscript
# core/game_state.gd
class_name GameState extends RefCounted

var day: int
var phase: String
var resources: Dictionary
var lin: Dictionary
var shelter: Dictionary
var bike: Dictionary
var car: Dictionary
var car_parts: Dictionary
var locations: Dictionary
var qimian: Dictionary

static func new_game() -> GameState:
```

**变化**：从 `Dictionary` 改为强类型 `class`，IDE 自动补全，防止拼写错误。

### 3.3 规则层（core/）

每个系统文件接收 `state: GameState` 参数，返回计算结果。**不持有状态，不 emit 信号。**

```gdscript
# core/exploration.gd
class_name ExplorationSystem extends RefCounted

static func enter_location(state: GameState, location_id: String) -> String:
    var location = state.locations[location_id]
    if location.range > state.bike.range:
        state.lin.fatigue += 1
        return "太远了。"
    state.exploration.active_location = location_id
    state.phase = "searching"
    return "进入 %s。" % location.name

static func search_room(state: GameState, room_id: String, tactic: String) -> String:
    # ... 返回搜索结果文本
```

```gdscript
# core/qimian_ai.gd
class_name QimianAI extends RefCounted

static func resolve_for_day(state: GameState, day: int) -> Array[Dictionary]:
    # 返回日志条目数组
    var plan = QimianPlan.get_for_day(day)
    if not plan.is_empty():
        return _execute_scheduled(state, day, plan)
    return _decide_and_execute(state, day)
```

### 3.4 流程调度层（GameManager）

```gdscript
# managers/game_manager.gd
class_name GameManager extends Node

signal state_changed()

var state: GameState

func _ready():
    state = GameState.new_game()
    state_changed.emit()

func on_explore_requested(location_id: String):
    if state.phase not in ["morning", "day"]: return
    ExplorationSystem.enter_location(state, location_id)
    state_changed.emit()

func on_search_room_requested(room_id: String, tactic: String):
    ExplorationSystem.search_room(state, room_id, tactic)
    state_changed.emit()

func on_sleep_requested():
    NightResolver.resolve(state)
    if state.day >= GameConstants.MAX_DEMO_DAY:
        NightResolver.finalize_demo(state)
    else:
        Simulation.start_day(state, state.day + 1)
    state_changed.emit()
```

**关键**：`state_changed` 信号是 UI 唯一的刷新触发器。UI 不主动轮询，不解构 state。

### 3.5 UI 层

```gdscript
# ui/main_ui.gd
class_name MainUI extends Control

@onready var manager: GameManager = $"/root/GameManager"

func _ready():
    manager.state_changed.connect(_on_state_changed)

func _on_state_changed():
    status_panel.refresh(manager.state)
    location_panel.refresh(manager.state)
    action_panel.refresh(manager.state)
    log_panel.refresh(manager.state)
```

**变化**：UI 只做两件事——(1) 绑定按钮信号到 `manager.on_xxx()`，(2) 收到 `state_changed` 后刷新显示。

## 五、"搜索房间"功能在新架构下的完整数据流

```
玩家点击「谨慎搜索：药房」
    │
    ▼
UI: room_card.gd
    → search_button.pressed.connect(manager.on_search_room.bind("pharmacy", "careful"))
    │
    ▼
GameManager: on_search_room("pharmacy", "careful")
    → 检查 state.phase == "searching" ? 是
    → 调用 ExplorationSystem.search_room(state, "pharmacy", "careful")
    │
    ▼
ExplorationSystem.search_room():
    → 读 LocationData.rooms_for("clinic")["pharmacy"]  ← 配置层
    → 判断 locked? searched? tactic?
    → 读资源：room.resources["meds"] = 4
    → 判断 hidden_zombies + visibility → 计算受伤
    → 写 state.resources.meds += 取量
    → 写 state.lin.health -= 受伤量
    → 读 flag → 写 state 旗标
    → 返回结果文本
    │
    ▼
GameManager:
    → state_changed.emit()  ← 唯一通知点
    │
    ▼
UI 各面板收到信号:
    - status_panel: 刷新生 命/疲劳/压力/感染
    - resources_panel: 刷新药品数量
    - room_card: 标记药房为「已搜」
    - log_panel: 显示搜索结果文本
```
