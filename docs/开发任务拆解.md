## 1. 程序任务拆解

### 执行规则

- 每次开发只推进一个明确任务编号，不把多个 P0 任务混写成一次“顺手一起做”。
- 每个任务在进入实现前，必须先写出“触发条件 / 玩家操作 / 系统状态变化 / 玩家可见反馈 / 验证方法”。
- 一个任务只有在“文档已更新 + 代码已实现 + 验证已记录”同时满足时，才能从进行中改成完成。
- 如果一个任务做完后仍然不知道怎么验证，说明任务拆分过大，必须继续拆小。
- P0 阶段优先保证可验证的交互闭环，不以功能数量作为主要进度指标。

### 单任务执行模板

后续每个 `C-xxx`、`U-xxx`、`D-xxx` 在进入开发前，统一先补下面这段短模板：

```text
任务编号：
功能名：
触发条件：
玩家操作：
系统状态变化：
玩家可见反馈：
涉及文件：
验证方法：
失败记录位置：
```

推荐的失败记录位置：

- Unity 实现问题：`docs/UNITY_STATUS.md`
- 范围失控或玩法偏移：`docs/MINIMUM_DEMO_SCOPE.md`
- 任务拆分不合理或优先级变化：`docs/开发任务拆解.md`

### 统一规格

- 角色：`32x32`，透明 PNG。
- 基础瓦片：`16x16`。

### 最低验收标准

- 一个素材进入 Demo 前，必须能在 2 倍或 3 倍缩放下看清主体轮廓。

## 8. 当前最适合招的队友

### 程序

优先需要会 Unity / C# 的队友，能接：

- 异常调查 + 隔空标记。
- 简单行动次数或行动点。
- 诊所 AI 链路和日志 UI。
- UI 面板接入。
- Unity Test Runner 自动测试。

### 像素美术

优先需要能做统一风格像素素材的队友，能接：

- 林行、祁眠、丧尸。
- 诊所、超市、修理铺/车库、据点。
- UI 图标和标记。
- 日志回放关键帧。

### UI / UX

优先需要能把灰盒界面做清楚的人，能接：

- 节点地图。
- 室内搜索界面。
- 未知行动者档案。
- 事件日志和祁眠日志界面。

### 策划 / 关卡

适合接：

- 4 地点最小纵切节奏。
- 诊所 AI 链路文本。
- Day 7 反馈验证。
- Day 15 日志揭示。

### 音频 / 视频包装

适合接：

- 末日环境音和 UI 音效。
- Demo 录屏。
- 比赛视频剪辑。
- PPT 视觉包装。

## 9. 下一步推荐排期

### 每次开发的固定节奏

1. 从本文件只选一个任务编号。
2. 先补“单任务执行模板”。
3. 再改代码或场景。
4. 回归对应 `T-xxx`。
5. 把结果写回相关文档。

只要第 4 步和第 5 步没做完，这个任务就不能算收尾。

### 第一优先级：跑通最小可玩纵切

1. 程序实现 `C-001` 到 `C-004`：Unity 编译验证 + 主界面 + 4 地点 + 基础日夜循环。
2. 程序实现 `C-005` 到 `C-009`：诊所异常 + 求助标记 + 祁眠反馈 + 结尾日志。
3. UI 实现 `U-001` 到 `U-008` 的最小版本。
4. 美术只做 `A-001` 到 `A-013`、`A-015`、`A-016` 的简化版。

### 第二优先级：最小行动取舍

1. 先做每日固定行动次数或简单行动点。
2. 不做完整骰子随机和拖放分配。
3. 只保证玩家每天有取舍。

### 第三优先级：比赛展示

1. 准备视频脚本和截图。
2. 用日志界面展示 AI 决策链。
3. 对外明确“完整版内容已规划，但本 Demo 聚焦最小纵切”。

### 暂缓

- 完整二周目。
- 14 地点全量实现。
- 复杂骰子系统。
- 长期 NPC 合作。
- 5 段回放动画。
